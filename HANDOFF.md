## 1. Install, run, build, test

Requirements: **Node.js 20+** (22 recommended; `.node-version` says 22), npm.

```bash
npm install                 # install dependencies
npm run dev                 # dev server → http://localhost:3000 (seeds .data/db.json on first request)
npm run build               # production build (Turbopack)
npm start                   # serve the production build
npm run lint                # ESLint
npm run typecheck           # tsc --noEmit
npm test                    # Vitest unit tests (51)
npm run test:e2e            # Playwright e2e (44) — run `npm run build` first
npm run demo:reset          # delete the demo database so it re-seeds on next start
```

- **E2E tests** start their own `next start` on port **3100** with `DATA_DIR=.data-e2e`, which is deleted and re-seeded by `tests/e2e/global-setup.ts`. They run serially with one worker. Chromium comes from Playwright 1.56.1 (in the cloud dev environment it's at `/opt/pw-browsers`; don't run `playwright install` there).
- If `PageProps` / `RouteContext` type errors appear after adding routes, run `npx next typegen` (Next 16 generates these global types).
- **Before every push:** `npm run lint && npm run typecheck && npm test && npm run build && npm run test:e2e`, and add a README change-log entry (see `CLAUDE.md`).

## 2. Deployment

- `render.yaml` Blueprint: one free web service `northline-prototype`.
  - Build: `npm ci --include=dev && npm run build`
  - Start: `npm start`
  - Health check: `/`
- **Env vars on Render:** `NODE_VERSION=22`, `NEXT_PUBLIC_DEMO_MODE=true`, `SESSION_SECRET` (auto-generated by Render), `DATA_DIR=/tmp/northline-data`. `RENDER_EXTERNAL_URL` is provided by Render and used as the site URL.
- **Auto-deploy:** every push to `claude/intelligent-edison-536z5s` redeploys the live demo in about 3–5 minutes. **Only push tested code to this branch while the client is reviewing.**
- **Free plan behaviour:** the service sleeps after about 15 minutes idle, and the first visit takes 30–60 seconds. The disk is temporary, so all demo data (orders, quotes, approvals, uploads, product edits) resets to the seed on every restart or deploy.
- **Safe deployment for the client review period:**
  1. Work on a separate branch (e.g. `phase2/...`) and open a PR. Don't push experimental work to the demo branch.
  2. Merge into the demo branch only after all checks pass.
  3. To roll back, revert the commit on the demo branch and push, or use **Manual Deploy → previous commit** in the Render dashboard.
  4. Demo mode must stay **on** for the demo. Anyone with the link can sign in with the demo accounts, so share the link only with the client.

## 5. Architecture decisions (and why)

1. **Server-resolved pricing.** Contractor prices are commercially sensitive, so they are resolved on the server and only the resulting price is sent to the browser. The cart and checkout re-price on the server.
2. **Session cookie holds only a signed user ID.** Role and contractor status are re-read on every request, so an approval or revocation takes effect immediately.
3. **Services behind interfaces** (payments, email, uploads, data store). Phase 2 swaps implementations, not UI.
4. **Pure business logic in `src/lib`**, unit-tested and free of I/O.
5. **JSON-file store** for zero-setup demos. It is **not** safe for multiple instances or concurrent production traffic.
6. **Locked design tokens.** Only the approved colours can be used, which prevents drift.
7. **Generated placeholder media.** No third-party or proprietary images were copied.
8. **Demo features gated on `env.demoMode`.** The toolbar, one-click sign-in and credentials hint all switch off together.

## 12. Known limitations and technical debt

- **JSON store**: single-process only. No transactions and no concurrency safety for counters or stock. Data is lost on Render restarts (free plan).
- **Simulated services**: payments, emails and SMS. No password reset or email verification (shown as "coming soon"). No rate limiting or CAPTCHA.
- **Uploads**: local disk, no virus scan, no retention policy.
- **Media**: generated SVG art and placeholder PDFs; plain `<img>` (the `no-img-element` lint rule is off on purpose until real images arrive).
- **Placeholder business data and policies** throughout (`business.isPlaceholder = true`).
- **Reference site not compared**: `nkflooring.pplx.app` was blocked by the build environment's network policy.
- **Single tax rate** and single contractor tier.
- **Time zone** is fixed to `America/Toronto` for display and admin dates.
- **Demo mode is on by default** (`NEXT_PUBLIC_DEMO_MODE` defaults to true). Production must set it to `false` explicitly.
- `src/components/forms/file-uploader.tsx` updates a ref during render (`latest.current = value`) to track files across async uploads. It works, but should become an effect or reducer when this component is next changed.
- The `.data/` and `.data-e2e/` folders are local runtime data (git-ignored). They are not backups.
